# 数据库运维

## 慢查询治理

- 开启慢查询日志，定期分析 top N 慢 SQL。
- 通过 explain 确认是否走索引、是否全表扫描。
- 避免在索引列上做函数运算或隐式类型转换导致索引失效。

## 连接池与锁

- 合理配置连接池大小，避免连接耗尽拖垮整个应用。
- 大事务要拆小，减少行锁和表锁持有时间。
- 关注死锁告警，通过锁等待日志定位相互等待的事务。

## 备份与恢复

- 每日全量备份 + 增量 binlog，备份要定期做恢复演练。
- 主从延迟超过阈值要告警，读写分离场景要注意数据一致性。
- 恢复演练验证备份可用性，避免"备份了但恢复不了"。

## 容量与分库分表

- 单表数据量过大时考虑归档或分库分表。
- 分库分表要选好分片键，避免跨库 join 和热点分片。
