# 故障排查手册

## 通用排查步骤

1. 确认影响范围：是单实例、单机房还是全量，是否与某次发布或配置变更相关。
2. 查看监控大盘，定位是延迟升高、错误率上升还是流量异常。
3. 拉取对应时间段的应用日志，按 traceId / requestId 关联链路。
4. 保留现场：抓取线程栈、堆内存、慢查询日志后再做恢复操作。

## 高延迟排查

- 先看调用链，确认慢在哪一跳：网关、应用、数据库还是下游服务。
- 检查线程池是否打满、连接池是否耗尽。
- 查看数据库慢查询和锁等待，必要时加索引或拆大事务。

## 高错误率排查

- 按错误码分类，定位是 4xx 业务错误还是 5xx 服务异常。
- 5xx 先看应用异常日志，确认是空指针、超时还是下游不可用。
- 检查是否触发了限流或熔断，是否因依赖服务抖动导致。

## 内存与 CPU 异常

- CPU 飙高：抓线程栈找热点线程，判断是 GC、死循环还是大量序列化。
- 内存上涨：导出堆转储，定位大对象或内存泄漏。
