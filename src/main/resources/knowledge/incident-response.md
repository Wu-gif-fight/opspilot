# 事故应急响应

## 响应原则

1. 先止损，再定位根因；优先恢复服务而不是争论责任。
2. 重大事故第一时间通知值班负责人并升级到 OnCall。
3. 全程记录时间线和操作，便于事后复盘。

## 止损手段

- 回滚：最近一次发布或配置变更导致的故障，优先回滚。
- 切换：故障集中在单机房或单实例时，先切走流量。
- 降级：关闭非核心功能或缓存兜底，保证核心链路可用。
- 限流：流量洪峰时对非关键接口限流，保护下游。

## 常见事故场景

- 服务宕机：先重启恢复，再查启动日志和资源水位。
- 支付失败：立即通知业务方，检查支付网关和订单状态，防止重复扣款或漏单。
- 数据不一致：暂停写操作，核对主从延迟或缓存与数据库差异，再修复数据。
- 数据库故障：先切换只读或主从切换，避免长时间不可写。

## 复盘

- 事故结束后 24 小时内完成复盘，产出根因、改进项和负责人。
- 改进项要可执行、可验收，并跟踪到闭环。
