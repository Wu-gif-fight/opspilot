# 部署发布指南

## 发布流程

1. 合并代码到 release 分支后，CI 自动构建镜像并推送到镜像仓库。
2. 先在预发环境部署，跑通冒烟用例后，再灰度到生产。
3. 生产发布采用滚动更新，每次只更新一个副本，观察 3 分钟再继续。

## 回滚策略

- 每次发布前记录上一个稳定版本号和镜像 tag。
- 发布后若错误率或延迟异常，立即执行 `kubectl rollout undo deployment/<name>`。
- 数据库变更必须向前兼容：先加列、后删列，禁止直接修改列类型。

## 配置管理

- 所有环境差异通过配置中心下发，禁止硬编码环境地址。
- 敏感配置（密钥、数据库口令）走密钥管理服务，不写入镜像或代码仓库。
- 配置变更需在预发验证后才推生产，并保留审计记录。

## 常见发布问题

- 镜像构建失败：优先检查依赖版本和构建缓存。
- 启动即退出：查看容器日志，确认配置是否缺失、端口是否被占用。
- 灰度比例：首次灰度建议 5%，稳定后逐步放量到 100%。
